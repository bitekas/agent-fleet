# Skills

Every skill in this directory, what it is for, and whether it is written to the
conventions in [`claude-skill/SKILL.md`](claude-skill/SKILL.md).

**Adding a skill means adding a row here in the same commit.** An index that is
only sometimes updated is worse than no index, because it is read as complete.

---

## The columns

| Column | What it means |
|---|---|
| **Skill** | The skill's directory name, linked to its `SKILL.md`. This is the name an agent loads it by. |
| **What it is for** | A one-line condensation of its purpose, for scanning the tree. **It is not the authoritative description** - that is the `description:` in the skill's own frontmatter, which is what an agent reads when deciding whether to load it. Condensed rather than copied on purpose: a verbatim second copy would drift from the first, and this table would then be quietly wrong about what a skill does. |
| **Conforms** | Whether the skill is written to the `claude-skill` conventions. Values below. |
| **Gap** | **What else** the skill needs, or what a reader has to know that the row does not say. It is a worklist, not a criticism. A `-` means nothing is owed. |

## What `Conforms` means

It answers one question, the test in
[`claude-skill/SKILL.md`](claude-skill/SKILL.md) section 6:

> Could a stranger at another company clone this skill, fill in
> `config.example.json` and `CONTEXT.md`, run `installation/check` until it
> exits 0, and have it work **without editing `SKILL.md`**?

| Value | Meaning |
|---|---|
| **yes** | Meets the layout and passes the test above. Frontmatter carries `version` and `requires_install`, no install value is named inline, and any script ships with its test. |
| **partial** | Mechanism and values are split, but the file contract is incomplete: a script without a test, an install without a `check`, or a value a stranger would still have to edit out. |
| **no** | Not converted. |

A skill directory here holds COMMON files only. Its SPECIFIC files -
`CONTEXT.md`, `config.json`, `installation/.install-state.json`, `temporary/` -
live in the install, resolved by `fleet where <skill>`.
