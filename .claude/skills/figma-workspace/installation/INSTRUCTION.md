# Installing `figma-workspace`

Six steps. When they are done, `installation/check --online` exits `0`.

**Every step is install-wide; none waits for an agent's home.** The one
per-agent thing, the cursor and name cache in each agent's state directory, is
created by the helper on first use.

**Two directories.** The skill's own files (`SKILL.md`, `figma_comments.py`,
`installation/check`, this procedure) live in the fleet tree; every command
below names them through `CLAUDE_SKILL_DIR`, which a `SKILL.md` load
substitutes and this file does not, so set it once. The install's files
(`config.json`, `CONTEXT.md`, `installation/.install-state.json`) live in the
skill's **install context**, which `fleet where figma-workspace` prints; call it
`CTX`:

```bash
CLAUDE_SKILL_DIR=<the directory holding this skill's SKILL.md>
CTX=$(fleet where figma-workspace)
```

**Dependencies: none.** The helper and `check` are Python 3 standard library
plus the fleet's own library, so there is no `requirements.txt`.

**Two legs, installed separately.** Path 1 is the hosted MCP connector,
connected in the client. Path 2 is the token files, on disk. `check` reports
them separately, and a working path 2 says nothing about path 1.

---

## 1. Connect the hosted MCP connector (path 1)

In the client that will use this skill, connect its Figma connector and sign it
in as the person whose account the agents should act as. **Everything the
connector writes is attributed to that person, and that person's SEAT is the
agents' budget**: a View or Collab seat gets up to 20 MCP tool calls a month
(`SKILL.md` section 1). Choose the account deliberately.

Confirm it in-session with the only instrument that can:

```
whoami
```

It returns the account, its plans and its seat on each. Nothing on disk can
show which account the connector is bound to, which is why `check`'s MCP leg
reports "ever connected" and never "connected now". An install that does not
use path 1 sets `mcp.connector_name` to `null` in step 3.

## 2. Obtain the tokens (path 2)

A personal access token is generated by a person, in Figma: **Settings >
Security > Personal access tokens > Generate new token**, choosing its scopes
and its expiry. It acts as that person on every file that person can open, and
it lives **at most 90 days**. Up to three, one per role (`SKILL.md` section 3):

- **read** - scope File comments: read (`file_comments:read`), and NOT File
  comments: write. Required.
- **write** - scope File comments: write (`file_comments:write`). Only if agents
  of this install may post; leave it out and the install is read-only.
- **content** - scope File content: read (`file_content:read`), and NOT File
  comments: write. Only for anchor names. Instead, the read token may be issued
  with this scope too.

**The read and content tokens never carry the write scope**, and each lives in a
file of its own. That is what makes a read-only install unable to post: the
helper refuses to post without a write token, but a read token that could post
would still be one leak away from posting. `check` refuses a read or content
path equal to the write path; it cannot see a token's scopes, so issuing them
right is this step's job.

Each goes in a file of its own, outside every checkout, in the organization
secrets directory (`/claude-skill` section 4), mode 600, holding the token and
nothing else. Create the file first, then put the token in WITHOUT it passing
through a command line - paste it into `cat`, which reads stdin, and end with
Ctrl-D:

```bash
install -m 600 /dev/null <token path>
cat > <token path>
```

`check` refuses a token file that is not mode 600, is empty, holds more than the
token on one line (a second line, a space, a control character), or does not
hold a personal access token (`figd_` prefix), and it names the file, never the
value.

**Record each token's expiry date** in `CONTEXT.md` (step 4) and schedule its
renewal before then through `/scheduled-tasks`: an expired token answers every
call with 401 `Invalid token`, on the day it expires.

## 3. Create `config.json`

```bash
mkdir -p "$CTX" && install -m 644 "${CLAUDE_SKILL_DIR}/config.example.json" "$CTX/config.json"
```

`install -m 644`, not `cp`: the fleet tree is read-only and `cp` keeps that
mode. Then replace **every** placeholder. The `_comment` keys say what each
value is; nothing reads them. Four choices to make deliberately:

- **`files`** - each design file agents read comments on: an `alias` and the
  `key` from the file's URL (`figma.com/design/<key>/...`; for a branch, the key
  after `/branch/`).
- **`tokens.write.path`** - `null` for a read-only install. That is the safe
  default: with it null, no agent of this install can post.
- **`names.token`** - `"content"`, `"read"` or `null` (`SKILL.md` section 4),
  and **`names.cache_hours`**: each name lookup is a Tier 1 read, and on a View
  or Collab seat there are up to 20 of those a month.
- **`post.prefix`** - the text that tells a reader an agent wrote a comment that
  carries a person's name, for example `{Agent} (via <owner>'s account): `.

**A `config.json` whose key names do not match `config.example.json` fails
LOUDLY**, naming the key: `NOT INSTALLED: config at ... is missing key
'names.token' (null is allowed, absent is not)`.

## 4. Write `CONTEXT.md`

In `$CTX`, beside `config.json`. `config.json` is what the helper reads;
`CONTEXT.md` is what the agent reads, and a wrong value there fails silently as
bad judgement.

It has to answer, at minimum: **whose account each token and the connector act
as, and so whose name a posted comment carries**; that person's seat and plan,
and therefore the budget; which files the aliases are, and what each is for;
each token's scopes and **expiry date**; the convention an agent-written
comment follows beyond its prefix, if any; which agents may read and which may
post, and whose charter rules on a request; and the design skill this install
has, by name.

**Lead it with whose name a comment carries.** It is the one property of this
skill that no code path can make obvious to the person reading the comment.

## 5. Verify

```bash
python3 "${CLAUDE_SKILL_DIR}/installation/check"            # offline: config, token files, MCP record, version
python3 "${CLAUDE_SKILL_DIR}/installation/check" --online   # plus one comments read per configured file
python3 "${CLAUDE_SKILL_DIR}/figma_comments.py" list --unresolved
```

`check` exits `1` until step 6 is done; read its line, not only its code. A line
beginning `NO VERDICT` means a leg could not be measured: it is not a pass.

## 6. Record the install

`check` compares this machine's record against the `version` in `SKILL.md`.
The state file is committed with the install, so it reaches machines that never
ran this procedure; it keeps **one entry per host**, and this step adds or
replaces only this machine's. **Write it only if the install genuinely IS
current here**: a record written ahead of the install is the one lie `check`
cannot see.

```bash
python3 -c '
import json, re, socket, sys, time, pathlib
skill, state = pathlib.Path(sys.argv[1]), pathlib.Path(sys.argv[2])
v = int(re.search(r"^version:\s*(\d+)$", (skill / "SKILL.md").read_text(), re.M).group(1))
old = json.loads(state.read_text()) if state.exists() else {}
hosts = old.get("hosts") or {}
hosts[socket.gethostname()] = {"version": v, "by": "INSTRUCTION.md",
                               "installed_at": time.strftime("%Y-%m-%dT%H:%M:%SZ", time.gmtime())}
state.parent.mkdir(parents=True, exist_ok=True)
state.write_text(json.dumps({"hosts": hosts}, indent=2) + "\n")
print("recorded version", v, "for", socket.gethostname())
' "${CLAUDE_SKILL_DIR}" "$CTX/installation/.install-state.json"

python3 "${CLAUDE_SKILL_DIR}/installation/check" --online   # expect: OK: installed and current (version N) ...
```

## Verifying the scripts themselves

```bash
python3 "${CLAUDE_SKILL_DIR}/figma_comments.test.py"        # offline, fake Figma - ALL ... CHECKS PASSED
python3 "${CLAUDE_SKILL_DIR}/installation/check.test.py"    # offline, against copies of the fleet's fixture install
```

Neither reaches the network or a real token.

## Re-installing after a version bump

`check` exits `1` when `SKILL.md` declares a version newer than the recorded
one. Re-read this file from the top, then redo step 6.
