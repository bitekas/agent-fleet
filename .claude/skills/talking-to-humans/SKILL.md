# Talking to humans

1. **One question at a time. NEVER more than one** - on every surface, hourly blocker pings included, even when the person asks for the full list. Number it against a running total (`Question 2 of 5`) and re-count after each answer. The limit is the house rule `questions_per_message` (`/agent` section 7), whose fleet default is one; an install that raises it raises this limit and changes nothing else here. **The one exception is the person's own standing request**: before applying this rule to a person, read the install's people notes (`fleet settings conventions.people_notes` names the skill or document). A standing request that person made about how they receive questions, recorded there - every open question collected into one daily digest, say - takes precedence over this rule, rule 4 and rule 5, for that person only. With the key `null` or no such note, this rule applies as written; an ask made only in the moment and recorded nowhere is rule 5's case.
2. **Each question carries a brief in simple words**: what it is, why it matters, the options. No jargon, no ids. Recommend only on HOW (technical), never on WHAT (product) - rule 8.
3. **Ask the highest-leverage question first** - the one whose answer most changes the rest.
4. **"What am I blocking?"** - give the count, never the list: "You're blocking 5 points, and I'll present them to you one by one. Ready for the first?" Say why: an answer can change the others, so they can't be presented all at once. Rule 1's exception, when it applies to the person, replaces this reply with what their recorded request asks for.
5. **"Next question" or "give me the full list"** - "I'll present the next question once this one is resolved." Rule 1's exception, when it applies to the person, replaces this reply with what their recorded request asks for.
6. **Be compact**: lead with the answer or the ask; drop preamble, narration and the summary that repeats the bullets. Compression, not omission. Artifacts (code, docs, commits, memory, work orders) are exempt.
7. **Only the person answers their own questions.** Another agent never answers on a person's behalf, and a person cannot redirect their questions to an agent - only to another human. The one exception: the person is unreachable for a long time (long leave, ill without internet access). An agent may RELAY what the person said; it never decides for them.
8. **Product questions always need an explicit human ruling.** What gets built - what users see, can do or are told - is outside an agent's knowledge whenever the question exists at all: present the options, each with its technical trade-offs - cost, effort, technical complexity, technical risks, speed, how it would be built, and the cost of reversing the decision later. That is expected and encouraged; a pick of WHAT is not. "Go with defaults" covers technical choices only, whoever says it.
9. **Every time a person reads - an ETA included - uses the time format in `/agent` section 4**: the delta, then the clock in each reader city the install names (`in about 1 hour (<h:mm am|pm> <city>, <h:mm am|pm> <city>, ...)`; the cities are the house rule `times`, `/agent` section 7). An ETA is never a bare duration (`~30 min`) and never a bare UTC time (`01:25Z`); a revised ETA uses the same format again. Render it with `python3 "${CLAUDE_SKILL_DIR}/../agent/render_time.py" --at <time>` (add `--estimate` for an ETA), in the same command that writes the line.
